# L009 — 跨时点对照必须同跑（生成器演进使旧档案不可逐位复现）

## Statement

任务生成器与 harness 代码随轮次演进（9/9→9/11 已发生 _TOKEN_RE 与问题模板
修订）。任何"旧结果 vs 新结果"的对照判定，**禁止引用旧档案数字直接比较**——
必须在同一轮用当前代码同跑对照组（same-run control）后再行判定。
旧档案的价值是历史记录与谱系，不是当前可比基准；引用旧档案数字必须注明
其生成器版本时点。

## Instances

- B-16（2026-09-16）：rag_2hop t4 初判 0.083 实为单跳回退分——与当日同跑
  plain rag 逐格一致后才定位正则-模板失配（当前 t4 问题模板无 "out of 5"）。
- B-19（2026-09-16）：确定性门初检 FAIL——误引修复前族 `microfw`
  （8892f40，难格 [0,0,0]）；修复后族 `micro_fw`（eb01dfc）才与新跑逐值一致。
- 同日 t1/t4 抽查：B-6/B-8 档案与当前生成器存在 1-2 题/格漂移
  （(64,0) 0.969→0.953、(4,4) 0.0→0.25 等）。

## Enforcement

- 任何对照类判定脚本必须包含 same-run 对照组；
- backlog/晨报引用旧档案数字时注明时点；
- judge 类常驻工具的档案映射指向最新权威族（见 judge_t45 修复先例）。
