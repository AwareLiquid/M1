# 事件原生传感流：为什么连续时间是结构必需，而非锦上添花

> 分支 `iter/event-stream-liquid` · 生成器 `benchmarks/event_stream.py` ·
> 基准 `benchmarks/event_bench.py` / `benchmarks/event_dt_span.py` ·
> 真实数据 `benchmarks/event_real_data.py`（N-Caltech101，尽力项）

## 一句话定位

事件相机的输出**不是"被干扰的规则流"，而是不规则即原生格式**：Δt 跨
微秒到秒多个数量级。离散循环架构（LSTM/GRU/Transformer）的 hidden 状态
按"步"演化，没有地方放"过了多久"；液态核心（连续时间 ODE 状态 + τ
时间常数）把 Δt 作为状态演化的积分变量——这是结构性差异，不是特征工程
能补的。Δt 当然可以作为输入通道喂给离散架构（我们的公平护栏就这样做），
但它只能被当作"又一个特征"，而不是"状态该衰减/积分多少"的一等公民。

## 为什么 patch 化 TSFM 不是同一件事

把事件流按时间窗切成 patch 再做注意力（TimesFM/Chronos 类思路的移植），
本质是把连续时间问题重离散化：

1. **窗长是新的采样率**。patch 越长，窗内多数量级的时间结构被压平；
   patch 越短，序列长度和 KV 内存回到 O(T) 老路。
2. **间隙信息只保留为标量特征**。一个 patch 内"100 个 1ms 事件 + 一个
   3s 静默"与"均匀 30ms 间隔"在 patch 表示里几乎不可区分；对连续时间
   状态，前者是"积分后长休眠"，后者是"持续慢积分"——动力学完全不同。
3. **KV 内存随事件数线性增长**。事件相机的价值在 µs 级峰值吞吐
   （>100 Mev/s），窗口方法在最需要它的场景内存爆掉；O(1) 状态的循环
   液态核心没有这个墙。

MIT CfC 系（Nature Machine Intelligence 2022, 无人机导航）是该方向的
学术血统；本仓库的差异是把同一主张放进"液态核心 + O(1) 记忆"组合，并
用 E0 协议（≥3 seeds、非双峰、配对检验）约束结论。

## 实验设计（预注册）

- **Δt 跨度压力测试**（`event_dt_span.py`）：跨度旋钮从 ~1.4 拉到 ~4
  个数量级（事件总量不变——拉宽不稀释），问退化曲线斜率谁最小。
  判定预写死：最宽档 mt_lnn vs 最强离散基线过 `publishable()`
  （p<0.05 且非双峰）**且** 差距随跨度拉大，才可声明"优势随跨度扩大"；
  否则记 Null。
- **τ 阶梯交互**：`mt_lnn_tau1`（τ 阶梯压到单时间尺度）在同一协议下
  对照——多尺度 τ 是否是跨度鲁棒性的来源。
- **护栏**：Δt（log 压缩）喂**所有**架构；gru_d 属
  `iter/irregular-streaming-edge`，未合入 main，记 `pending merge`，
  不本地重写。

结果（含 Null）见 [RESULTS.md](../RESULTS.md) 与
`benchmarks/results/event_*.json`。

## 结果摘要（2026-08-29 跑完，10 seeds）

- **状态估计**：mt_lnn 在全部 3 档事件密度是唯一打赢常数预测器的架构
  （nRMSE 0.974/0.750/0.978 vs 离散基线 0.81–1.30），最宽 Δt 跨度档
  （3.24 个数量级）显著最优（vs lstm 9/10 seed 胜，p=0.0215）。
- **"优势随 Δt 跨度扩大"= NULL**（预注册 gate_b 失败：差距 0.141→0.044
  随跨度收窄，所有架构都随跨度变容易）。连续时间的价值体现在
  **每一档都最优**，而不是"跨度越大越拉开"。
- **诚实的负结果**：下一事件通道预测上 mt_lnn 在密集事件档**显著差于**
  lstm/gru（0.227 vs 0.33）——连续时间积分有利于状态携带，无助于类别
  预测。
- **真实数据（N-Caltech101）= Null**：mt_lnn 0.545±0.031 vs gru
  0.520±0.027，5胜3负 p=0.727，无显著差异。
