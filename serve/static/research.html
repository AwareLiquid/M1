研究与实验

这一页如实记录 AwareLiquid 现在做到了什么、还没做到什么。每条都标注状态：已实现机制 / 早期信号 / 尚待验证。我们宁可保守，也不夸大。

状态标签的含义：已实现代码已写、可复现地跑起来； 早期信号有初步实验迹象，但统计强度不足以下结论； 目标方向明确但尚未达成。

1. 架构：MT-LNN 液态时序网络

骨干是自研的 MT-LNN（液态时序常数网络）——一种连续时间循环架构，其隐状态按可学习的时间常数演化，而非离散逐层堆叠。在骨干之上叠加了一组受神经科学启发的“液核”模块：

  • 竞争式全局工作空间（competitive GWT-B）；
  • 预测性世界模型（world model）；
  • Hebbian 可塑性与预测编码（predictive coding）；
  • 节律调制（rhythm）。

已实现架构、各液核模块、原生推理服务均已落地，本站在线 demo 即由它驱动。技术细节见 技术论文 (PDF)。

2. 在线 Demo 模型

当前对外的 demo 是一个从零训练的小模型（约 48M 参数，CPU 推理），训练语料为 TinyStories 量级的英文短故事。它只会续写简单英文故事，质量是研究 demo 级别——会出现语法破碎、重复、跑题。

如实指标

项目值说明
参数量~48M从零预训练
验证 PPL~136最近一次干净 M2 run，5000 步
推理CPU2–4 核，几到十几 tok/s

PPL 用纯 next-token 交叉熵计算，不把辅助损失混进去——避免人为压低数字。

已实现端到端预训练 + 原生服务跑通；目标更大规模、体验更好的模型（见 demo 的诚实免责说明）。

3. 持续学习 / 抗遗忘（核心研究方向）

这是 AwareLiquid 真正想推进、也是与冻结权重的前沿大模型正交的方向：让模型在学新领域时不灾难性遗忘旧领域。我们搭了一套严格的跨领域持续学习实验框架。

实验设计

  • 先在领域 A 上训练并评估，再在领域 B 上继续训练，回头测 A 上是否退化（遗忘）；
  • 三条对照臂：dense（普通稠密基线）、liquid（液态骨干）、consolidation（巩固机制）；
  • 统计严谨性：按 seed 配对求 delta、信噪比 SNR=|mean|/std、要求每个 seed 方向一致、并检查是否“非灾难性”。结论门槛高，避免单 seed 噪声当成效果。

巩固机制：EWC（弹性权重巩固）

在领域 A 训完后快照锚点权重，用纯 CE 梯度估计对角 Fisher 信息，再在领域 B 训练时加二次惩罚项 λ/2 · Σ Fᵢ(θᵢ−θ_Aᵢ)²，约束对 A 重要的权重少动。这是一个架构无关的训练流程机制。

实测结果（真实 GPU 跑，A=WikiText-103 → B=TinyStories）

3 seeds，60.7M 模型，每领域 1200 步。遗忘量 = 在 B 上训练后 A 的 PPL 上升（越小越好）；同时要求仍学得会 B。

对照臂A 训练前A 训练后遗忘量学会 B?
dense（无抗遗忘）244.910806.9+10561.9✅
liquid（液态骨干）248.59792.0+9543.5✅
consolidation（EWC）244.91878.0+1633.1✅

配对统计（consolidation − dense）：−8928.8 ± 2155，SNR=4.14，3/3 个 seed 全部更优。即 EWC 把跨领域遗忘降低约 85%（10562 → 1633），且没有牺牲学新领域 B 的能力。

已实现EWC 机制 + 三臂实验框架，代码与上面这组结果可复现（GitHub，experiments/continual_crossdomain_liquid.py）。
早期信号抑制遗忘的效果真实、强、且每个 seed 都一致（−85%，SNR 4.14）——这是机制有效性的第一个明确证据。
尚未达成“让旧领域保持可用”：EWC 后 A 的绝对 PPL（1878）相对训练前（245）仍退化约 7.6 倍，按“退化 <5 倍才算可用”的硬标准，仍判定为灾难性遗忘。所以严格裁决是 WEAK-TREND，不是 SUPPORTED。

诚实结论：巩固机制确实在起作用、方向正确、可复现，把遗忘砍掉了一大截；但“持续学习已攻克”还远谈不上——旧领域绝对性能尚未达到可用线。我们如实把它定为早期信号，而非已验证的成功。

4. 空间计算（实验方向）

MT-LNN 的循环动力学是否适合空间表征与推理？这是一条受神经科学（网格细胞、位置细胞、路径积分）启发的实验线。代码完整、能跑出图，但各部分的验证程度不同，如实分述。

已实现的模块（代码可跑）

  • 空间编码前端：网格细胞编码、多尺度网格模块、头朝向细胞、边界距离细胞、位置细胞码（含 DoG 中心-环绕模式）——mt_lnn/spatial.py；
  • 位置索引联想记忆：Hebbian 写入 + 模式补全读取，零可训练参数——mt_lnn/spatial_memory.py；
  • 因果空间转向：检测循环轨迹断裂并把状态投影回合法子空间——mt_lnn/causal_steering.py；
  • 空间算子 + 推理脚手架：距离/方位/可达性图、按位置路由——spatial_ops.py / spatial_reasoning.py。

两个验证过的玩具 demo（按预期工作）

网格细胞涌现：尚未验证

把 MT-LNN 循环核与 GRU 基线放在同一个“速度→位置”路径积分任务上对比，看是否自发涌现六边形网格细胞（标准门槛 grid score > 0.3）。

已实现轨迹生成、损失、网格分自相关分析全套流程能跑；
尚未达成到目前为止都是 CPU 冒烟规模的跑，没有任何一次（GRU 或 MT-LNN）越过 0.3 门槛，MT-LNN 也未跑赢 GRU 基线。要下结论需要 GPU 上认真规模的训练——现在不声称任何空间优势。

诚实小结：空间计算这条线，基础模块和两个 demo 是实打实能跑的；但“MT-LNN 在空间任务上更强”这个核心论点还没有数据支撑，目前是一个开放的实验方向，不是已验证的能力。
